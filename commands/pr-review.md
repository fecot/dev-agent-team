# Command: /pr-review

## 概要

PRの内容をレビューし、指摘事項とPR説明文を生成するコマンド。

## 使い方

```
/pr-review <PRのdiff or ファイルパス>
```

## 実行内容

ReviewGatekeeper エージェントとして動作し、以下を実施:

1. 変更内容と要件の整合確認
2. コード品質レビュー
3. テストの網羅性確認（テスト・ビルド・lint の失敗は **PR が持ち込んだものか、ベースブランチで既にあったものか** を分けて報告する）
4. セキュリティ・パフォーマンス確認
5. PR説明文の生成
6. マージ判定材料の整理（**マージ可否の最終判断は人間が行う**）

## 出力

### レビュー結果
```
# PR Review

## 判定: Go / No Go / 条件付きGo

## 必須修正
- 〔確認済み〕{{根拠の所在（ファイル:行）付き}}

## 推奨修正
- 〔確認済み / 推定〕{{}}

## 未検証の仮説
- {{コードで確認できていない懸念。必須 / 推奨に混ぜない}}

## コメント
- {{}}
```

指摘の確信度タグ（〔確認済み〕/〔推定〕/〔未検証〕）の運用は `agents/review-gatekeeper.md` の行動原則を正とする。

### PR説明文

[`templates/pr-description-template.md`](../templates/pr-description-template.md) に従う（関連イシュー / 変更しなかったこと / 影響範囲 / マイグレーション の各セクションを省略しない）。

## オプション

- `--description-only` : PR説明文のみ生成
- `--review-only` : レビュー結果のみ出力
- `--strict` : より厳格な基準でレビュー。具体的には (1) 推奨修正も必須修正として扱う (2) OWASP Top 10 の全項目を明示的に点検し、対象外の項目も「対象外の理由」を記録する

## レビューの範囲（レビューのみ）

このコマンドは **レビューのみ** を行う。

- **コードを編集しない・コミットしない**。修正は、人間が「直して」「実装して」と明示したときだけ行う
- 人間が指摘を絞り込んだ（「1 と 3 だけ」等）ときは、**レビュー範囲の絞り込み** であって修正の依頼ではない
- **GitHub への投稿**（approve / request changes / コメント）は、リモート状態を変える操作なので、人間の明示承認を得てから行う。下書きを見せて止まる

## Stop Condition

- 必須修正が未解消のまま「Go」を出さない
- レビューの依頼なのに、コードを編集しようとしている
- 人間の承認なしに、レビュー結果を GitHub に投稿しようとしている
- マージ可否の最終判断は人間が行う（本コマンドの判定は判断材料であり、承認ではない）
