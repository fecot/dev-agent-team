# Skill: 影響範囲分析

> 主に Phase 3（Impact Analysis）で使用する。

## 概要

コード変更の波及範囲を特定するスキル。ArchitectureReviewer エージェントが使用する。

## 分析の観点

### コードの依存関係
- 変更対象の関数・クラスを使っているコード
- 変更対象が依存しているコード（双方向を確認）
- 共有ユーティリティ・ヘルパーへの影響

### データへの影響
- DBスキーマの変更が必要か
- 既存データの整合性に影響するか
- マイグレーション手順が必要か

### API・インターフェースへの影響
- レスポンス形式の変更
- 引数の変更（後方互換があるか）
- 外部クライアントへの影響

### データ取得の共有関係（複数箇所が同じ API を使う場合）
- 共有判定は **「エンドポイント + パラメータ」** で行う。**表示・見た目で判断しない**（同じ API を使う画面同士の表示は似ているとは限らず、表示が似ていてもパラメータが違えば別呼び出しが正しい）
- **エンドポイント → 利用箇所のマトリクス** を作り、Phase 3 の成果物に含める（表示内容で並べない）
- 作成時の注意（取りこぼしやすい手順）:
  - **定数名と URL 文字列の両方で grep する**。ファイル内で定数が再定義されていると片方しか出ない
  - **共有フック / 共通コンポーネント経由の間接参照も追う**。直接の API 呼び出しだけを数えると漏れる
  - **コードの共有と実行の共有は別物**。「共有フックを作った」は「リクエストが 1 本になった」を意味しない（呼び出し箇所ごとに実行される）。実行回数は実測で確認する

### テストへの影響
- 変更対象をテストしているファイル
- モック・スタブの修正が必要か

### 非機能要件への影響
- パフォーマンス（ループ内の処理追加、N+1）
- セキュリティ（認証・認可の変更）
- ログ・モニタリングへの影響

## 深刻度の基準

| 深刻度 | 基準 |
|-------|------|
| 高 | 本番データに影響 / 認証・認可に関わる / 外部APIへの影響 |
| 中 | 既存機能の振る舞いが変わる / テストの修正が必要 |
| 低 | 新規追加のみ / 内部リファクタリング |
